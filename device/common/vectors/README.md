# IronMesh wire-format conformance vectors

Machine-readable test vectors for every structure in [`WIRE_FORMAT.md`](../WIRE_FORMAT.md) and
[`DELTA_FORMAT.md`](../DELTA_FORMAT.md). They are generated by the Python reference implementation
(`python -m ironmesh_wire vectors --out device/common/vectors`) and consumed by the Rust agent
(`device/agent-rs`) and the ESP32 firmware (`device/esp32`) test suites. The Python consumer that
exercises every file - and therefore documents the expected use of each field - is
`libs/python/ironmesh-wire/tests/test_vector_files.py`.

## Conventions

* Every file is a JSON object with `schema_version` (currently `1`), `description` and `generator`.
* Byte strings are lower-case hex in fields whose names end in `_hex` (or `hex`). Keys are given as
  PKCS#8 / SubjectPublicKeyInfo PEM **and** as raw bytes (`public_raw_hex`: 32-byte Ed25519 key or
  65-byte uncompressed P-256 point; `private_seed_hex` for Ed25519, `private_scalar_hex` for P-256).
* `expect` is `"accept"` or `"reject"`; rejections carry the exact `error` code from
  `WIRE_FORMAT.md` §8 / `DELTA_FORMAT.md` §6 that a conforming implementation must report. Codes
  are part of the specification; the check order in the spec determines which code wins.
* **Deterministic vs. verification vectors.** Ed25519 signatures, canonical CBOR, HPKE with fixed
  ephemeral keys and the delta format are fully deterministic: implementations MUST reproduce the
  given bytes. ECDSA (ES256) signatures are randomized and ML-DSA-65 signing is hedged, so
  device-signed envelopes and the hybrid manifest are *verification* vectors: implementations MUST
  accept them and reject the tampered variants, but regenerate different (equally valid) bytes.
  Each file states which kind it is (`deterministic` flag or the description).
* All test keys are public test material (`libs/python/ironmesh-wire/tests/keys`). Never use them
  outside tests.

## Files

| File                          | What it proves                                                                 |
|-------------------------------|--------------------------------------------------------------------------------|
| `cbor_canonical.json`         | `valid[]`: diagnostic notation -> the unique canonical encoding (`hex`); encoders must produce exactly `hex`, decoders must accept it and re-encode to the same bytes. `invalid[]`: inputs the strict decoder must reject with `error`. `limits` gives the default size/depth/tag limits. |
| `cose_sign1_es256.json`       | COSE_Sign1 with ES256 (verification only): `cases[]` give payload, protected header, `Sig_structure` and the full message; `negative[]` give tampered messages and the required error; `verify_with` names the key to use (`key` or `wrong_key`). |
| `cose_sign1_eddsa.json`       | Same with Ed25519 (deterministic: `message_hex` must be reproduced from `key.private_seed_hex`). |
| `envelope_telemetry.json`     | A Telemetry envelope: body fields -> `payload_hex` (must match exactly), `wire_hex` must verify with `device_key` at `now`. |
| `envelope_command_ack.json`   | A Command (tenant-signed, deterministic) and its CommandAck (device-signed); nonce echo and `ack_bad_nonce` rejection. |
| `manifest_signed.json`        | Manifest fields -> `manifest_hex`; `signed_ed25519_only_hex` (deterministic); `signed_hybrid_hex` with ML-DSA-65 (verification only; `null` if the generator had no PQ backend); `verify_cases[]` (trusted keys = `trusted_pubkeys_hex`); `acceptance_cases[]` for the pure `accept_image()` rules. |
| `delta_*.json`                | `apply(old, patch) == new` and (reference encoder) `make(old, new) == patch`; `copy_ops` / `literal_bytes` statistics. `delta_invalid.json`: patches that must be rejected with `error` (`old_hex: null` means the shared base). |
| `hpke_rfc9180_a3.json`        | RFC 9180 Appendix A.3.1 (DHKEM(P-256)/HKDF-SHA256/AES-128-GCM, base mode) plus `config_encrypt0`: an IronMesh Config message wrapped as COSE_Encrypt0 with fixed CEK/IV/ephemeral ikm (reproducible if those hooks exist; decryptable by everyone). |
| `attestation_software.json`   | Attestation envelope (type 10) for a software-keyed device plus policy rejections. |
| `replay_cases.json`           | An ordered sequence of envelopes against one replay store: seq rules, timestamp window (both directions, boundaries), signature/key/direction failures, nonce rules, unknown type; `store_after` gives the expected store state after each step. |
| `ids_topics.json`             | Identifier regex cases, key-id derivations and the full MQTT topic table. |

## Consuming the vectors (per file)

**cbor_canonical** - for each `valid` entry: `decode(hex)` must succeed, `encode(decode(hex)) ==
hex`, and if your implementation can parse diagnostic notation, `encode(parse(diag)) == hex`. For
each `invalid` entry `decode(hex)` must fail with `error`. Depth counts the top-level item as 1.

**cose_sign1_*** - parse `message_hex` (tag 18); check `protected_hex`, `payload_hex`,
`sig_structure_hex` (`["Signature1", protected, h'', payload]`) and `signature_hex`; verify with
`key.public_pem`. For `negative` entries, decode+verify with the key named by `verify_with` must
fail with `error` (structural errors are raised by the parser, `COSE_SIGNATURE` by the verifier).

**envelope_*** - build the payload map from `message.body` (hex fields are byte strings, `type`
is the map key 3, `nonce_hex` key 5), canonical-encode it and compare with `payload_hex`. Then run
the full `decode` procedure of `WIRE_FORMAT.md` §3.6 on `wire_hex` with the given keys, `now` and
an empty replay store. For deterministic (tenant-signed) messages also compare the produced
`wire_hex`.

**manifest_signed** - encode the manifest and compare with `manifest_hex`; sign with
`ed25519_key` and compare with `signed_ed25519_only_hex`; run `verify_cases` with
`trusted_pubkeys_hex` as the bundle's `fw_signing_pubkeys`; run `acceptance_cases` through
`accept_image(manifest, image, current_version_code, product)` and compare `(accepted, reason)`.
Implementations without ML-DSA skip the hybrid `require_pq = true` accept case (they must still
reject `require_pq = true` on the Ed25519-only manifest with `COSE_PQ_REQUIRED`).

**delta_*** - `apply_delta(old, patch)` must equal `new`; `make_delta(old, new)` should equal
`patch`. Feed the patch to a streaming applier in several chunk sizes.

**hpke_rfc9180_a3** - reproduce the RFC values (`derive_key_pair(ikmR)`, `encap` with `ikmE`,
key schedule, the listed `encryptions` at their sequence numbers, `exports`). For
`config_encrypt0`, `unwrap(encrypt0_hex, device_key) == plaintext_hex`; `plaintext_hex` is itself a
tenant-signed Config envelope (deterministic, `plaintext_message` describes it); the `negative`
entries must fail with `error`.

**attestation_software** - verify `message.wire_hex` with `device_key` as the TLS client key,
`expected_nonce = nonce_hex`, `csr_der = csr_der_hex`, `now`; the `negative` entries override one
input each and must fail with `error`.

**replay_cases** - start with an empty replay store and process `steps` in order with the key
resolver {`device_kid_hex` -> `device_key`, `tenant_kid` -> `tenant_key`}, `expected_tenant =
tenant_id`, `max_skew`, each step's `now` and (when present) `expected_nonce_hex`. Compare the
outcome, the error code and `store_after`.

**ids_topics** - validators must accept/reject the listed identifiers and topics; `key_ids` give
the kid derivations.

## Regenerating

```sh
.venv/Scripts/python -m ironmesh_wire vectors --out device/common/vectors
```

Only the verification-only files change between runs (fresh ECDSA/ML-DSA randomness); every other
file is byte-identical. Bump `schema_version` and this README whenever a field is added or renamed.
